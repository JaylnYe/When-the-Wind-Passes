# 风经过

全屏树木交互原型。树主体没有说明文案、计数或减少动态开关；树下方有梧桐叶、银杏叶、樱花切换栏，右下角保留轻吹与重置两个图标按钮，支持键盘和读屏。

运行：`python3 -m http.server 8765 --directory dist`，打开 http://localhost:8765 。无需构建。Node 18+ 模拟测试：`node --test tests/*.test.js`。

## 互动与长叶

三种可切换的树形：梧桐叶、金黄银杏与樱花，每棵有 1650 片独立叶子。按住鼠标或单指划动产生局部风；原叶直接脱落，留下真实缺口。树冠少于约 1238 片时启动补叶，逐片恢复到完整状态。每 0.16 秒最多开始长一片，新叶用 2.4 秒由小变大，并有 3 秒成熟保护期。全树至少保留 660 片枝头叶，各细枝至少保留 3 片，避免吹秃。落叶消失后才复用其对象，数量不会无限增长。

叶片受风后会在约 0–0.42 秒内分批离枝；每片叶子的阻力、摆动和旋转速度略有差异。接近地面时转动减缓，落地后停留约 1.6–2.5 秒，再逐渐淡出。下层枝条抬高，露出更长的主干和落叶空间。无操作时约每 2.8 秒自然飘下一片，随后原枝补叶；系统减少动态偏好下关闭自然飘落。

没有页面级减少动态开关，但仍自动尊重系统偏好：关闭摇摆、空间飘落和缩放生长，使用原位淡入淡出。固定 120 Hz 物理步，无操作且无生长任务时休眠，后台暂停，不补算离开期间的时间。

## 验证

十项模拟测试覆盖静止、身份守恒、脱落连续性、分批离枝与落地停留、局部风、系统减少动态、重置、帧率独立，以及持续吹动不吹秃、最终恢复长满。浏览器检查脚本在 qa/；先安装 Playwright，启动本地服务后运行。可用 CHROME_EXECUTABLE_PATH 指定本机 Chrome。已检查桌面与 390×844 模拟布局；不代表 iOS/Android 真机性能验收。

## 素材与边界

枫树的 5 个运行时叶片纹理来自用户提供的 wind_tree_realistic_mobile_assets.zip（leaf-01、04、07、11、18）；银杏叶与樱花由 imagegen 生成透明素材，代码中着色并独立绘制。枝条、背景、布局与代码为重建；没有固定树冠底图。其他纹理作为参考保留。原素材来自扁平参考图近似分离，未额外确认商业授权。

当前为完整树的结构与交互原型，非写实原画还原。叶柄转轴与地面接触采用简化处理；任意输入采样率下的严格轨迹重采样、原画细节和真机表现仍需后续验证。

## 树形重建

人工配置主干与不对称分叉；固定种子生成长度、角度不同的细枝和叶簇芽点。骨架围绕树根纵向拉高 16%、横向收窄 12%，使整体更修长，也让下层主干露出更多。叶片分前后两层，绿黄纹理在加载时预处理；前层色彩略深，后层更小、更柔和。枝干使用渐细轮廓与细纹。去掉显眼的树根，只保留轻微的接地阴影。静止形态固定，风只影响枝条姿态。当前 1650 片叶的手机真机性能仍待测量。

手机竖屏使用更近的画面取景，并将叶片绘制尺寸提高 18%，让树冠和单片叶子更容易看清；桌面取景保持原样。

银杏树使用独立的高挑枝干骨架和扇形叶片素材；樱花使用展开的枝冠和独立花朵。每棵树增加 300 片枝冠内层的独立叶片或花朵，避免只在枝梢形成稀疏叶簇。背景有柔和暖光，树冠中局部叶片更亮；切换树种时重建该树的独立叶片，沿用风、落叶与补叶机制。
